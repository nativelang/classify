# Contributing to Classify

Help a new reader see something useful in the first few lines. For an API, start with the simplest useful call and show the part of the result the reader needs. For a setup guide, say what the reader will have running and why they would want it.

Write for junior programmers and product managers. Show what the reader can do, why it helps, and where it fits in their work. Give the exact steps, fields, and limits when they need to act. Name things the way a reader would describe the task. Bring in implementation details only when they change what the reader needs to do. Introduce technical terms where they first matter. [How to review Classify writing](.agents/skills/review-classify-writing/SKILL.md)

When the user supplies a clear example, keep it as the starting point. In the first classification example, show the actual text, categories, and answer together. Label shared code examples as pseudocode. Keep SDK details for the reader who is ready to write code. For a specific language, run the example as written and check its result before publishing.

Keep a line of code, prose, or example only when removing it would cost the reader something or change behavior someone relies on.

For every change, including documentation, work on a branch and open a pull request. Merge it into `main` after required checks and reviews pass.
